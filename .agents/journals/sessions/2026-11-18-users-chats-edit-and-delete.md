# Редактирование и удаление пользователей и чатов

## Проблема

Оба раздела были read-only: у пользователей `canCreate/canEdit/canDelete` возвращали `false` и формы не было; у чатов
редактирование отсутствовало, удаление было только на странице просмотра (`ViewMaxChat`) без транзакции и защиты от
ссылок хост-приложения. Нужно было добавить изменение и удаление записей в локальной БД для обоих разделов.

## Решение

Создание оставили запрещённым. Пользователь правится на странице `EditMaxUser` формой `Resources\Schemas\MaxUserForm`:
имя, фамилия, никнейм, отображаемое имя, описание, телефон, e-mail и отметка «бот». Чат правится на странице
`EditMaxChat` формой `Resources\Schemas\MaxChatForm`: название, описание, ссылка, URL иконки. Служебные поля (у
пользователя — `user_id`, аватары, отметки; у чата — `chat_id`, тип, статус, отметки) не редактируются: их ведёт
синхронизация или реестр.

Права и Policy-классы вынесены в `laravel-max-client`: код ресурса — префикс permission-строки (`max_user` /
`max_chat`), ability — `view.any`, `view`, `edit`, `delete`, `manage`; `create` в контракт не входит, потому что реестр
наполняется вебхуками. Бридж регистрирует `Gate::policy()` для моделей `users.model` / `chats.model`; плагин только
привязывает ability к UI (`Gate::allows('viewAny'|'view'|'edit'|'delete'|'manage', ...)`) и больше не содержит своих
Policy, `ResourceGate`, секции прав и ключей `users_model` / `chats_model`. Старые `users.*` / `chats.*` и
`FILAMENT_MAX_USERS_PERMISSION_*` удалены (BC), настройка прав — в `laravel-max-client` (`MAX_PERMISSION_*`).

Удаление вынесено в общие действия `DeleteMaxUserAction` и `DeleteMaxChatAction`: в транзакции сначала удаляются строки
`max_chat_users`, затем запись `max_users` / `max_chats`. Если на запись ссылается хост-приложение (внешний ключ),
`QueryException` откатывает транзакцию: связи не теряются, показывается уведомление об отказе, исключение уходит в лог
без чувствительных данных. Прежний inline-метод удаления в `ViewMaxChat` удалён.

## Тесты

- страницы редактирования: сохранение разрешённых полей, точный состав форм, 403 без `max_user.edit` / `max_chat.edit`;
- видимость и скрытие действий `edit` и `delete` в списках и на просмотрах;
- удаление пользователя и чата вместе со связями `max_chat_users`, редирект в список;
- откат удаления при ссылке из хост-таблиц (`host_profiles`, `host_chat_links` с внешними ключами);
- локализация: подписи ресурсов на ru/en, статусы чатов и fallback названия из бриджа, паритет ключей `lang/ru` ↔
  `lang/en`.

## Нюансы

- В таблицах `EditAction` пришлось авторизовать явно: в контексте таблицы авто-авторизация Filament не отдала скрытие по
  `canEdit()`.
- SQLite-тесты включают `PRAGMA foreign_keys = ON`, поэтому отказ по внешнему ключу воспроизводится без моков.
- Добавленные permission-строки и env-переменные аддитивны внутри новой схемы; старые `users.*` / `chats.*` удалены,
  хосту нужно переназначить права ролям. Права и Policy живут в `laravel-max-client`; без обновлённого vendor бриджа
  плагин fail-closed скроет разделы.
- Подписи в конфиге (`label`, `plural_label`, `navigation_label`) по умолчанию `null`: значения берутся из `lang/ru` и
  `lang/en` по текущей локали; конфиг — только override.
- В конфиге бриджа ability `view.any` хранится ключом `view_any`: точка в ключе ломает доступ через `config()`.
- Даты больше не форматируются жёстким `d.m.Y`: используется `->dateTime()` с форматом панели Filament по локали;
  удалены неиспользуемые lang-ключи (`view.title`, `is_bot_yes/no`, `full_avatar_url`, `actions.edit`).
- `last_activity_time` приходит из MAX в миллисекундах и теперь переводится в Carbon через
  `UserPresenter::lastActivityAt()`; без этого дата отображалась как 2000 год.
- В русских lang-файлах выровнены подписи: `Chat ID` → `ID чата`, `User ID` → `ID пользователя`, `Обновлён` →
  `Профиль обновлён`, `Тип` → `Тип пользователя`.
- Подтверждение телефона: `phone_verified_at` заполняет бридж при подписанном контакте; переключатель «Сбросить
  подтверждение телефона» очищает отметку, не удаляя номер; изменение номера сбрасывает подтверждение автоматически.
- Клик по строке списка пользователей и чатов ведёт на страницу просмотра (а не редактирования); чаты пользователя на
  просмотре кликабельны, кнопки «Изменить»/«Удалить» — в шапке. После сохранения — редирект в список.
- В списках добавлены иконки «Обновить из MAX», «Просмотр», «Изменить», «Удалить»; refresh вынесен в общие
  `RefreshMaxUserAction`/`RefreshMaxChatAction`. Клик по строке ведёт на просмотр только при праве `view`.
- Кнопки просмотра упорядочены refresh → edit → delete и оформлены outlined с иконками; на редактировании тот же стиль у
  delete, «Открыть пользователя», Save и Cancel.
- Диалог: форма редактирования показывает read-only контекст (ID, тип, статус, имя собеседника), metadata-поля и
  сохранение скрыты; в шапке — «Открыть пользователя».
