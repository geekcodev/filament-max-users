# Инициализация проекта и базовой документации

## Проблема

Проекта не было: требовалось зафиксировать архитектуру, правила работы агента и план до написания кода, чтобы реализация
не разошлась с замыслом.

## Решение

- Создан `AGENTS.md` — проектный контекст, правила для ИИ-агентов, обязательный Gate, OWASP Top 10, локальная разработка
  (по образцу `/home/user/web/filament-max-broadcasts/AGENTS.md`).
- Создан рабочий план `PLAN-filament-max-users.md` с разделами: принятые решения (§0), цели и объём (§1), структура
  репозитория (§2), публичный API (§3), конфигурация (§4), миграции/таблицы (§5), описание двух разделов (§6–7),
  инфраструктура (§8), тесты (§9), Gate (§10), порядок реализации (§11), журнал сессий (§12), открытые вопросы (§13).
- Заведён каталог рабочей памяти `.agents/` (`JOURNAL.md` + первый файл в `sessions/`).

Изученные источники (эталон реализации): `filament-max-broadcasts` — структура `src/`, Plugin, ServiceProvider, конфиг,
lang, тесты, Gate, Docker, журнал; `laravel-max-client` — модели `MaxUser` (PK `user_id`, связь `maxChats()`),
`MaxChat`, enum
`MaxChatStatus`, сервис `MaxUserProfileService` (`refresh()`/`ensureAvatar()`/`upsertFromMember()`), миграции
`max_users`/`max_chats`;
`max-php-client` — `ApiClient` (`getChat(int $chatId)`, `getChatMembers`).

Принятые решения: один плагин регистрирует два ресурса (`MaxUserResource`, `MaxChatResource`) в одну navigation-группу
`Max`; собственные миграции и таблицы не создаём — реестр берём из `laravel-max-client`; обновление профиля только через
`MaxUserProfileService::refresh()`, без дублирования логики клиента; детальный просмотр чата — данные реестра плюс
связанный пользователь, `ApiClient::getChat` опционален; редактирование отсутствует, удаление — только локальной записи
чата `MaxChat`.
