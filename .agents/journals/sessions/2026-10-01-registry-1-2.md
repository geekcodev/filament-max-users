# Переход на laravel-max-client 1.2 / max-php-client 1.1.8

## Проблема

Зависимости отстали от последних релизов, а `laravel-max-client` 1.2.0 — ломающий релиз: форма реестра чатов стала «одна
строка на чат» с PK `chat_id` и отдельной таблицей связей `max_chat_users`. Ресурсы плагина на старой форме падали с
`AttributeError` на отсутствующих колонках.

## Решение

- Зависимости: `laravel-max-client` ^1.2.0, `max-php-client` ^1.1.8; транзитивно Filament v5.7.8, Laravel 13.34.0,
  Livewire 4.4.3.
- Раздел «Max чаты» переведён на `chat_id`: метаданные из `getChat`, тип, статус, счётчик и список участников
  `chatUsers`,
  `chat_checked_at`, действие «Обновить из MAX» через `MaxChatProfileService::sync()` по новому праву `chats.manage`,
  удаление записи вместе со строками связей.
- Раздел «Max пользователи»: телефон с иконкой подтверждения, e-mail, имя, описание, аватар, `profile_checked_at`,
  счётчик по `chatLinks`, фильтр «С телефоном», список чатов на странице просмотра.
- Новые `Support\ChatPresenter` и `Support\UserPresenter` — атрибуты читаются через `getAttribute()`, потому что модель
  переопределяется конфигом.
- Тесты переписаны под новую форму реестра, добавлен `tests/Unit/Support/PresenterTest.php`; action-тесты идут через
  настоящие final-сервисы с подменой PSR-18 транспорта (`tests/Fixtures/MockHttpClient.php`, `fakeMaxApi()`).
- README, `AGENTS.md` и план обновлены.

Ключевые решения: `sync()`, а не `refresh()` для действия на странице чата — `refresh()` пропускает чаты со свежим
`chat_checked_at`, а открытый администратором чат нужно обновить принудительно; сервисы `laravel-max-client` объявлены
`final` и не мокаются, поэтому подменяется PSR-18 клиент и тест идёт по настоящему пути через `ApiClient`;
`searchable(['title'])` — в Filament v5 именованного параметра `columns` больше нет; счётчики задаются именами связей
`counts('chatUsers')` и `counts('chatLinks')`, потому что Filament v5 ждёт имя связи, а не имя колонки
`chat_users_count`; в `phpstan-baseline.neon` только записи о Livewire-хелперах из `tests/`, в `src/` записей нет.

## Тесты

30 тестов / 107 утверждений, все зелёные. Feature-тесты ресурсов идут по настоящему пути через final-сервисы, unit-тесты
presenters — на реальной модели и на переопределённой конфигом.

## Нюансы

- `php artisan max:upgrade` обязателен после `migrate`, иначе реестр остаётся в старой форме; это зафиксировано в
  README.
- Packagist в этой сети зависал на IPv6, `composer update` шёл через временный IPv4-конфиг вне репозитория.
- Черновик release notes на этот релиз не писался: переход ломающий для хостов на 1.1.x, номер версии решён позже —
  release notes `v1.1.0` подготовлены в сессии `2026-10-01-workflow-coverage-gate.md`.
- Осталась проверка в реальной панели хоста: аватары по внешним URL, `max:upgrade` на живых данных, выдача
  `chats.manage`.
