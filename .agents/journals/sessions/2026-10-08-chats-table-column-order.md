# Порядок колонок и полей в разделе «Max чаты»

## Проблема

Запрос: задать последовательность в списке чатов — ид, тип, статус, название, пользователей, последняя активность — и на
детальной странице — Ид, иконка, тип, статус, название, описание, ссылка, последняя активность, метаданные обновлены.
Старый порядок был другим: в таблице первыми шли иконка и название, статус был после счётчика; на просмотре — иконка,
название, id, тип, «Название из MAX», описание, ссылка, статус.

## Решение

`MaxChatsTable::configure()`: порядок `chat_id`, `chat_type`, `status`, затем скрытая `icon_url`, `displayName`, скрытая
`title`, `chat_users_count`, `last_activity_at`, скрытая `chat_checked_at` — видимая часть ровно «ид, тип, статус,
название, пользователей, последняя активность». `ViewMaxChat::infolist()`: `chat_id` → иконка → тип → статус →
`displayName` → описание → ссылка → `last_activity_at` → `chat_checked_at` → участники.

Raw `title` («Название из MAX») на детальной странице убран по итогам обсуждения: у групп и каналов он дублирует
`displayName`, у диалогов пуст, признак получения метаданных даёт `chat_checked_at`. В списке `title` оставлен скрытой
колонкой (включается тулбаром колонок) — как сырое значение для отладки; lang-ключ `chats.view.title`
сохранён в обоих языках (BC: имена lang-строк не удаляются).

В `lang/{ru,en}/chats.php` убран мёртвый дублирующий ключ `view.title` («Детали чата»/«Chat details»): он
перезаписывался вторым `view.title` («Название из MAX»/«Name from MAX») и никогда не показывался — поведение UI не
менялось.

## Тесты

`MaxChatResourceTest`: `test_list_shows_columns_in_expected_default_order` (видимые колонки — ровно запрошенная
последовательность), `test_view_page_shows_entries_in_expected_order` (список entries infolist, включая
`chatUsers` последним). Идентичны по стилю тестам порядка из `MaxUserResourceTest`.

## Нюансы

- Скрытые колонки (`icon_url`, `title`, `chat_checked_at`) участвуют в порядке массива, но не влияют на видимую
  последовательность, пока выключены тулбаром колонок.
- На просмотре `description` остаётся с `columnSpanFull()` — при любом порядке поле занимает всю ширину.
