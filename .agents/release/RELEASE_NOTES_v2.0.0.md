# v2.0.0

Большой релиз 2: переход на ядро `geekcodev/max-php-client` **v2.0.0** и адаптер `geekcodev/laravel-max-client`
**v2.0.0**, управление локальными записями пользователей и чатов и Policy-схема прав.

## Новое

- Синхронизация с ядром и адаптером v2: constraints подняты до `^2.0` (предрелизная ветка `new` ставит `dev-new` из
  Packagist). Код плагина под типизированные события MAX не менялся — он работает через реестр и DTO профилей.
- Пользователи: страница редактирования профиля и контактов (имя, фамилия, никнейм, отображаемое имя, описание, телефон,
  e-mail, отметка «бот») и удаление из локального реестра в транзакции вместе со связями `max_chat_users`. Добавлен
  переключатель «Сбросить подтверждение телефона»; при изменении номера подтверждение сбрасывается автоматически.
- Чаты: страница редактирования метаданных (название, описание, ссылка, URL иконки; ссылка и иконка принимаются только с
  http/https), строчное действие удаления и транзакционное удаление вместе со связями `max_chat_users`.
- Удаление в обоих разделах вынесено в общие действия `DeleteMaxUserAction` и `DeleteMaxChatAction`: при ссылке из
  хост-приложения (внешний ключ) транзакция откатывается, связи не теряются, показывается уведомление об отказе.
- Действия «Изменить» и «Удалить» доступны в строке списка и на странице просмотра обоих разделов. Клик по строке списка
  ведёт на страницу просмотра, а не редактирования; чаты пользователя на просмотре кликабельны. После сохранения на
  странице редактирования выполняется редирект в список.
- Диалог в форме редактирования чата показывает read-only контекст (ID, тип, статус, имя собеседника) и пояснение;
  metadata-поля и сохранение скрыты, в шапке — «Открыть пользователя».
- Диалог в форме редактирования чата показывает read-only контекст (ID, тип, статус, имя собеседника) и пояснение;
  metadata-поля и сохранение скрыты, в шапке — «Открыть пользователя».
- Права и Policy-классы живут в `laravel-max-client`: `MaxUserPolicy` / `MaxChatPolicy`, enum-ы `MaxUserPermission` /
  `MaxChatPermission`, конфиг `laravel-max-client.permissions`, env `MAX_PERMISSION_*`. Плагин только привязывает
  ability к UI (`viewAny`, `view`, `edit`, `delete`, `manage`).
- Permission-строки: `max_user.view.any`, `max_user.view`, `max_user.edit`, `max_user.delete`, `max_user.manage` и такие
  же с префиксом `max_chat`. `manage` закрывает только «Обновить из MAX». `create` в контракт не входит: реестр
  наполняется вебхуками, ручное создание пакетом не поддерживается.
- Подписи ресурсов по умолчанию берутся из `lang/ru` и `lang/en` по текущей локали: `ui.*.label`, `plural_label`,
  `navigation_label` в конфиге по умолчанию `null` и служат только осознанным override для приложения.
- Локализация доведена до конца: статусы чатов и fallback-название чата приходят из `laravel-max-client::*`, даты
  выводятся форматом панели Filament по локали вместо жёсткого `d.m.Y`, удалены неиспользуемые lang-ключи, добавлен тест
  паритета ключей `lang/ru` ↔ `lang/en`. Русские подписи выровнены: `ID пользователя`, `ID чата`, `Тип пользователя`,
  `Профиль обновлён`.
- Исправлено отображение `last_activity_time`: MAX хранит его в миллисекундах, теперь значение переводится в секунды
  через `UserPresenter::lastActivityAt()`; раньше дата уезжала в 2000 год.
- В коде хоста доступны обе формы проверки: `$user->can('viewAny', MaxUser::class)`, `$user->can('edit', $chat)` и
  привычные permission-строки `$user->can('max_user.manage')`.

## Изменение (BC)

- Constraints: `geekcodev/max-php-client` `^1.1.8` → `^2.0`, `geekcodev/laravel-max-client` `^1.2.0` → `^2.0`
  (предрелизная ветка `new` — `dev-new`).
- Права `users.*` / `chats.*` полностью заменены; старые ключи и env-переменные больше не читаются. Соответствие:

  | Было | Стало |
        |---|---|
  | `users.view` | `max_user.view.any` + `max_user.view` |
  | `users.manage` | `max_user.manage` |
  | `users.edit` | `max_user.edit` |
  | `users.delete` | `max_user.delete` |
  | `chats.view` | `max_chat.view.any` + `max_chat.view` |
  | `chats.manage` | `max_chat.manage` |
  | `chats.edit` | `max_chat.edit` |
  | `chats.delete` | `max_chat.delete` |

  Хосту нужно переназначить права ролям. Настройка прав переехала в `config/laravel-max-client.php` (env
  `MAX_PERMISSION_*`); секция `permissions` и переменные `FILAMENT_MAX_USERS_PERMISSION_*` из конфига плагина удалены.
- Ключи моделей `users_model` / `chats_model` из конфига плагина удалены: ресурсы берут модели из
  `laravel-max-client` (`users.model` / `chats.model`). Это убирает расхождение, когда Policy зарегистрирована для
  одного класса, а ресурс работает с другим.
- Env-переменная `FILAMENT_MAX_USERS_NAVIGATION_GROUP` удалена: плагин больше не читает env вообще, группа разделов
  задаётся в `config/filament-max-users.php` (`ui.navigation_group`, по умолчанию `Max`). Файл `.env.example` удалён.
- Даты в таблицах и infolist больше не используют жёсткий `d.m.Y`: формат задаёт панель Filament по локали. Статусы
  чатов в английской локали теперь `Active`/`Stopped`/`Removed`, а не русские подписи из enum-а.
- Создание пользователей и чатов недоступно (`canCreate()` → `false`); права `create` в контракте нет.
- Миграций и публичных методов ресурсов изменения не касаются; схема реестра остаётся формой `laravel-max-client` 2.x.

## Затронутые сценарии

- Администратор с `max_user.edit` / `max_chat.edit` открывает запись и меняет разрешённые поля; служебные поля и отметки
  синхронизации остаются только для чтения.
- Администратор с `max_user.delete` / `max_chat.delete` удаляет локальную запись вместе со связями с чатами.
- При попытке удалить запись, на которую ссылается приложение, показывается отказ, данные остаются нетронутыми.
- Без `view.any` раздел недоступен, без `view` недоступна карточка записи; без `edit` / `delete` страница редактирования
  отдаёт 403, действия скрыты.
- Обновление профиля и метаданных по-прежнему идёт через `MaxUserProfileService::refresh()` и
  `MaxChatProfileService::sync()` по праву `manage`.
