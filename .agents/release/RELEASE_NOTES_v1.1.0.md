# v1.1.0 — новая форма реестра `laravel-max-client` 1.2, метаданные чата и обновление чата

Переход на новую форму реестра `laravel-max-client` 1.2: раздел «Max чаты» переведён на `chat_id`, добавлены метаданные
чата из MAX API и обновление чата по требованию. Релиз ломающий для хостов на `laravel-max-client` 1.1.x — порядок
обновления обязателен.

### Новое

- Метаданные чата из MAX API: `title`, `chat_type`, `status`, описание, ссылка, иконка, время последней активности и
  отметка
  `chat_checked_at`. Название чата берётся из `title` у группы и канала, у диалога — имя собеседника, иначе `chat_id`
  (`Support\ChatPresenter`).
- Действие «Обновить из MAX» на странице чата: `MaxChatProfileService::sync($chatId)` — один запрос `getChat` заполняет
  метаданные и обновляет `chat_checked_at`. Отличие от `refresh()`: `refresh()` пропускает чаты со свежей отметкой, а
  администратор открыл конкретный чат и ждёт принудительного обновления.
- Новое право доступа `chats.manage` на действие обновления чата; ключ конфигурации `permissions.chats.manage` и
  переменная
  `FILAMENT_MAX_USERS_PERMISSION_CHATS_MANAGE` (по умолчанию `chats.manage`).
- Раздел «Max пользователи»: телефон с иконкой подтверждения (`phone_verified_at`), e-mail, имя, описание, аватар,
  отметка последней синхронизации `profile_checked_at`, список чатов пользователя и фильтр «С телефоном».
- В чате: список участников с их статусом взаимодействия и счётчик по связи `chatUsers`.
- Удаление записи чата удаляет и строки `max_chat_users` — внешних ключей между таблицами нет.

### Изменение (BC)

- Требуемая версия `geekcodev/laravel-max-client` повышена с `^1.1.1` до `^1.2.0`, `geekcodev/max-php-client` — до
  `^1.1.8`. На `laravel-max-client` 1.1.x ресурсы не работают: у моделей `MaxChat`/`MaxChatUser` нет `title`,
  `chat_type`,
  `chat_checked_at` и `status`.
- Форма реестра изменилась: одна строка на чат, PK `chat_id`, связи вынесены в `max_chat_users`. Обновление обязано
  выполнять
  `php artisan migrate`, затем `php artisan max:upgrade` (есть `--dry-run` и `--rollback`). Пропуск второго шага
  оставляет старую форму реестра, и разделы показывают пустые или битые данные.
- Добавлено право `chats.manage`: у пользователя без него действие «Обновить из MAX» на странице чата недоступно. Для
  существующих установок право нужно выдать администраторам, иначе действие не появится.
- Исправлены тексты подписей в `lang/en`: `resource.label` и `resource.plural_label` содержали русский текст. Ключи не
  менялись.
- Переформулированы подписи аватаров и счётчиков чатов, добавлены подписи состояний синхронизации. Ключи lang-строк
  прежние, изменились только значения.

### Затронутые сценарии

- Установка и обновление: обязательные `migrate` + `max:upgrade`, новая переменная
  `FILAMENT_MAX_USERS_PERMISSION_CHATS_MANAGE`.
- Просмотр чатов: работает по `chat_id` вместо прежней формы записи; добавлены метаданные из MAX и участники.
- Обновление из MAX: у пользователя — `MaxUserProfileService::refresh()`, у чата — `MaxChatProfileService::sync()`.
- Права: у чата появилось отдельное право на обновление; удаление записи чата по-прежнему требует `chats.delete`.
- Локализация: `lang/ru` и `lang/en` синхронизированы, ключи совпадают.

Инструкция по обновлению существующей установки:

```bash
composer require geekcodev/filament-max-users:^1.1.0
php artisan migrate
php artisan max:upgrade
php artisan vendor:publish --tag=filament-max-users-config --force
```

`max:upgrade` обязателен именно при переходе с реестра 1.1.x — он переносит данные и пересобирает `max_chats` под форму
«одна строка на чат». Команда идемпотентна и имеет `--dry-run` и `--rollback`; на чистой установке достаточно одного
`php artisan migrate`, ставить `max:upgrade` не нужно. Публикация конфига с `--force` нужна, чтобы в приложении появился
ключ `chats.manage`; без него действует дефолт `chats.manage`, выдача права остаётся на администратора хоста.
